# 本地三维工作台

## 流程排查修复（2026-11-24）

- 修复小图预处理只缩小、不放大的问题。现在等比例适配到 454×756 前景范围，再居中到 504×840；允许插值放大，但不恢复原图缺失细节。预处理 JSON 记录前景尺寸和缩放倍率。历史任务不重写。
- 主高斯查看器关闭渐显，导出 PNG 前等待完整排序，并暂时禁用相机交互，避免采集到局部尚未显示的画面。
- 实际上传照片的三路渲染、同一小图修复前后的 GPU 推理对照，见 `evaluation_user_20261124/index.html`。本机评估服务运行时可访问 http://127.0.0.1:8771/evaluation_user_20261124/index.html 。官方 CUDA 与网页 1× 前景并集平均绝对差约 1.91–2.93/255；这是输出差异，不是重建准确率。
- 当前部署仍为 LHMPP-700M-SMPLX-FREE；本地官方 app.py 默认的 LHMPP-700M-PixelShuffle 尚未下载或实测，不能混用两者的效果结论。

## 清晰度改进（2026-10-26）

- 新任务优先使用本机已校验的完整 U²-Net 抠图权重（175,997,641 字节）；未安装时退回 u2netp。保留用户 PNG 的透明通道，并扩大裁剪范围以保留柔和边缘。完整模型不保证每张照片都优于轻量版。
- 网络输入仍为 504×840、输出仍为 16 万高斯，未擅自修改预训练结构。每张参考图旁保存 `.preprocess.json` 记录抠图方式、尺寸和耗时。
- 高斯查看器新增 1× / 1.5× / 2× 显示分辨率，默认 2×；2× 每方向采样翻倍，像素总数约为 1× 的四倍。它改善显示采样，不会补出 PLY 中不存在的纹理。
- 保留低透明度高斯的阈值从 5 降为 1，减少细薄边缘被提前删除，也可能显示更多浮点。采用连续渲染以兼容浏览器截图与画面更新。
- 渲染库本地扩展 `renderPixelRatio` 同步设置投影和绘制尺寸。高清模式显卡负载更高，可切换流畅模式。
- 历史 PLY 不会自动重新生成；要使用新抠图，请重新提交原照片。

双击“启动三维工作台.cmd”，访问 http://127.0.0.1:8770/studio.html 。

已实现：
- 单张 JPG/PNG/WebP 本机上传，TripoSR CUDA 推理、抠图、完整网格生成。
- 单张照片通过 LHM++ 本机 WSL 推理生成标准姿态 Gaussian PLY，约一分钟，16 万高斯；可在下拉框选择生成后端。已对两张不同人物照片完成有效性验证，详见 README_LHM_VERIFY.md。
- 导入标准 3DGS Gaussian PLY，检查高斯属性与数值；组员原文件已作为样例收录。
- 本地 GaussianSplats3D 0.4.7 + Three.js 0.160.0 真正的高斯渲染，旋转、缩放、正侧背面、翻转上下、当前视角 PNG 导出。
- 网格交互预览与 GLB/PLY 导出，高斯保留原 PLY；两者不进行伪转换。
- 磁盘持久化历史任务、日志、实测速度和显存、输出文件下载；同一服务内 GPU 生成串行。
- 浏览器代码与模型文件全部本地加载，不向第三方查看器发送照片或模型。

组员原 PLY 未携带模型名称或生成过程，仍不能确认确切来源。现在已独立部署并验证 LHM++，可以从照片生成同类高斯表示；不声称与组员使用同一版本或能得到完全相同结果。

验收：网页样例生成已实测 10.8 秒、1.94GB PyTorch 峰值显存；高斯导入测试 160000 点成功，非法 PLY 返回 400。具体硬件、图片和首次启动成本会影响速度。

每个任务在 studio_results/<id>/，record.json 标记真实来源、类型、状态和下载文件。生成失败详情保留在 run.log。停止窗口不会删除历史记录。重启后可继续浏览已完成任务，但被中断的任务不自动恢复；不要同时从旧演示启动 GPU 推理。
